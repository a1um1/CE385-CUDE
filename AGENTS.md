# AGENTS.md

Full-stack competitive-coding course platform. npm-workspaces monorepo: `client/` (Vite + React + TanStack Start/Router/Query, port 5173) and `server/` (Express 5 + Prisma + Postgres 18, port 3000). Requires Node.js >= 24. Linter/format are OXC (`oxlint`, `oxfmt`), **not** ESLint/Prettier.

## Commands (run from repo root)

- `npm run dev` — starts client + server concurrently (`tsx watch` on server).
- `npm run ts:check` — client `tsc`, then server `prisma generate && tsc --noEmit`. Server typecheck will fail if the generated Prisma client is stale.
- `npm run lint` / `npm run format:check` — oxlint / oxfmt, per workspace.
- `npm run test -w server` — Vitest (client intentionally has no tests).
- `npm run openapi:generate` — rewrites `client/src/data/base/openapi.ts` from `http://localhost:3000/openapi.json`. **The server must be running.** Commit the regenerated file alongside API changes.
- `npm run docker:up` — Postgres 18 container, host port **5434** (not 5432), env from `scripts/.env.local`.
- `npm run judge0:up` — go-judge sandbox on port 5050 (privileged container, needs `DOCKER_DEFAULT_PLATFORM=linux/amd64` — already in the script).
- `npm run generate-routes -w client` — regenerate `routeTree.gen.ts` after adding/renaming files in `client/src/routes/`.

CI (`checker.yaml`, any push to `feat/*|bug/*|dev/*|develop`): ts:check + lint + format:check per workspace, plus server Vitest with coverage. Local equivalent before pushing: `npm run ts:check && npm run lint && npm run format:check && npm run test -w server`.

## Workspace imports & aliases

- Both packages are `"type": "module"` with strict TS (`verbatimModuleSyntax`, `noUncheckedIndexedAccess`). Use `import type` for type-only imports; index-based access needs bounds checks.
- Path alias `#/*` resolves to `./src/*` (client) / `./src/*.ts` (server). Prefer `#/...` imports over relative paths.

## Server (CUDE) conventions

- Prisma schema is **split across multiple files** in `server/src/prisma/` (`schema.prisma`, `user.prisma`, `course.prisma`, `log.prisma`, `currencies.prisma`, `exercise/`, `submission/`). Add tables/models to the relevant file, not only `schema.prisma`. Migrations live alongside in `src/prisma/migrations/` (`npm run db:migrate -w server`).
- Generated client is gitignored (`server/src/generated/prisma/`), generated by `prisma generate`. Import it as `#/generated/prisma/...`.
- `dbml/schema.dbml` is auto-generated by `prisma-dbml-generator` — do not edit by hand.
- Routes use a custom `CustomRouter` (`server/src/lib/router/customRouter.ts`); every route's zod schemas auto-register into the OpenAPI registry. The `response` schema is parsed at runtime, so handlers must return exactly what it declares.
- Use `z` from `#/lib/extendZod` (OpenAPI-aware), not `zod` directly.
- Errors: throw `UserError(status, message)`; `z.ZodError` → 400, `UserError` → its status, anything else → 500.
- DB is mocked in tests (`server/src/test/setup.ts` exports `mockDB` from vitest-mock-extended); no live DB needed. Vitest config sets a test `JWT_SECRET` and uses `pool: "forks"`.
- Server config from `server/.env` (see `.env.example`; `DATABASE_URL`, `JWT_SECRET`). Runtime needs the Postgres from `docker:up`.

## Client conventions

- File-based routing via TanStack Router. `client/src/routeTree.gen.ts` is committed and ignored by oxlint/oxfmt, but must be regenerated after route changes (or Vite dev does it).
- API types come from committed `client/src/data/base/openapi.ts` (openapi-fetch). Regenerate via `openapi:generate` after server endpoint/schema changes; oxlint/oxfmt ignore this file.
- CSS Modules `.module.css.d.ts` are generated by `vite-css-modules` and gitignored; run `npm run css:generate -w client` if types for a new module are missing.
- Uses `#/*` → `src/*`; API base is `VITE_API_URL=http://localhost:3000` in `client/.env`.

## Git workflow

- `develop` is push-protected. Work on feature branches (`feat/*`, `bug/*`, or `dev/*`), one branch per feature/item. PRs require 2 approvals and green CI.
